What this page is, and what it is notこのページが何であり，何でないか

The community repository leanprover-community/riemann-hypothesis publishes a procedure for checking the project with lake comparator. This page records our own run of that procedure on RIKYU (RIKEN R-CCS), with the deviations listed below. It is not the verification carried out by the community, and it is not a statement by the community; for those, see the repository and the statement linked at the top of the Overview. As everywhere in this report, the page states what was run and what came out, and does not assess the mathematics.

Deviations from the procedure of the communityコミュニティの手順との相違点

Our run differs from the published procedure in the following points.

我々の実行は，公表されている手順と次の点で異なる．

  1. The checker “Lean paranoid” is not run. The program leanchecker-paranoid of the Lean 4.36.0 release for aarch64 aborts at start-up on these nodes, also when it is called with --version only (message “INTERNAL PANIC: integer overflow in runtime computation”, exit code 134; the nodes use a page size of 64 KiB), so the failure does not depend on the input. lake comparator counts a checker that cannot start as a rejection. The job therefore tests whether the program starts and, if it does not, removes exactly this entry from the configuration and records that it did. The result of our run can therefore be at most “accepted by nanoda and by the Lean default kernel”; it is not a result for the complete configuration of the community.検査器「Lean paranoid」は実行していない．aarch64 用の Lean 4.36.0 リリースに含まれる leanchecker-paranoid は，このノードでは起動時に異常終了する．--version だけを指定しても同じである（メッセージは「INTERNAL PANIC: integer overflow in runtime computation」，終了コード 134．ノードのページサイズは 64 KiB）．したがってこの失敗は入力によらない．lake comparator は，起動できない検査器を拒否として数える．そこでジョブは，このプログラムが起動するかを調べ，起動しない場合に限り，設定からこの項目だけを取り除き，そのことを記録している．このため我々の実行の結果は，最良でも「nanoda と Lean の既定のカーネルによる受理」であり，コミュニティの設定全体に対する結果ではない．
  2. The solution was not built by this job inside a sandbox without network access.
